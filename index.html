ZETA Pro

A modular, open-source Luau UI library for Roblox script hubs. Build customizable interfaces, extend components, and create your own experience with full control over the design.

local Zeta = loadstring(game:HttpGet("https://raw.githubusercontent.com/realkalii/ZetaPro/main/src/init.luau"))()

Quick start

  1. Install

    Run this in your executor. ZetaPro loads itself, and running it again replaces the previous instance.

  2. Create your first window

    This example creates a window with a button, toggle, slider and dropdown.

    local Zeta = loadstring(game:HttpGet("https://raw.githubusercontent.com/realkalii/ZetaPro/main/src/init.luau"))()
local Window = Zeta:CreateWindow({
    Title = "ZETA Pro",
    SubTitle = "Quick start",
    Theme = "Zeta",
    MinimizeKey = Enum.KeyCode.RightControl,
})

local Main = Window:AddTab({ Title = "Main", Icon = "home" })
local Section = Main:AddSection("Basics")

Section:AddButton({
    Title = "Say hello",
    Description = "Shows a notification",
    Callback = function()
        Zeta:Notify({ Title = "ZETA Pro", Content = "Hello!", Type = "Success", Duration = 3 })
    end,
})
Section:AddToggle("Enabled", {
    Title = "Enabled",
    Default = true,
    Callback = function(on) print(on) end,
})

Section:AddSlider("Speed", {
    Title = "Speed",
    Min = 16,
    Max = 100,
    Default = 50,
    Callback = function(value) print(value) end,
})
Section:AddDropdown("Mode", {
    Title = "Mode",
    Values = { "Option 1", "Option 2", "Option 3" },
    Default = 1,
    Callback = function(value) print(value) end,
})
  3. Explore

    Press RightControl to hide or show the window, then keep going.

Installation

Get started with ZETA Pro in just one line of code.

local Zeta = loadstring(game:HttpGet(
    "https://raw.githubusercontent.com/realkalii/ZetaPro/main/src/init.luau"
))()

Run this code to load the latest published version of ZETA Pro. Running it again automatically unloads the previous instance.

Specific versions

Use a release tag to load a specific version. Set ZETA_BASE so the loader and its modules use the same tag.

getgenv().ZETA_BASE = "https://raw.githubusercontent.com/realkalii/ZetaPro/v1.0.2/src/"
local Zeta = loadstring(game:HttpGet(getgenv().ZETA_BASE .. "init.luau"))()

Release tags must exist in the repository before they can be used. Replace v1.0.2 with an existing tag, such as v1.0.1.

Load from a fork or branch

getgenv().ZETA_BASE = "https://raw.githubusercontent.com/you/ZetaPro/dev/src/"
local Zeta = loadstring(game:HttpGet(getgenv().ZETA_BASE .. "init.luau"))()

Replace you with your GitHub username and dev with your branch name.

GitHub may temporarily cache raw files. After updating your repository, it might take some time for your changes to appear.

Quick start

Create your first window, add a tab and section, and start building your interface with components.

local Zeta = loadstring(game:HttpGet("https://raw.githubusercontent.com/realkalii/ZetaPro/main/src/init.luau"))()

local Window = Zeta:CreateWindow({
    Title = "ZETA Pro",
    SubTitle = "Example",
    Size = UDim2.fromOffset(520, 380),
    Theme = "Dark",
    Acrylic = true,
    MinimizeKey = Enum.KeyCode.RightShift,
})

local Main = Window:AddTab({ Title = "Main", Icon = "home" })
local Section = Main:AddSection("Basics")

Section:AddButton({
    Title = "Hello",
    Callback = function()
        print("Hello from ZETA Pro!")
    end,
})

local Enabled = Section:AddToggle("Enabled", {
    Title = "Enabled",
    Default = false,
    Callback = function(value)
        print("Enabled:", value)
    end,
})

Enabled:SetValue(true)

The optional first argument ("Enabled") is a unique component ID. Components with IDs are available through Window.Options.Enabled and store their values in Zeta.Config. Callbacks run when values change, not when a component is created.

Window

local Window = Zeta:CreateWindow({
    Title = "ZETA Pro",
    SubTitle = "v1.0.2",
    Icon = "terminal",
    Size = UDim2.fromOffset(520, 380),
    TabWidth = 160,
    MinSize = Vector2.new(420, 320),
    MaxSize = Vector2.new(1000, 800),
    Theme = "Dark",
    Acrylic = true,
    Blur = true,
    Resize = false,
    CloseButton = false,
    SearchEnabled = true,
    MinimizeKey = Enum.KeyCode.RightShift,
})

Acrylic enables the translucent surface, while Blur = false keeps transparency without screen blur. Resize shows a resize grip, and CloseButton displays an X (OnClose runs before Destroy()).

Window.Options provides access to components by their unique IDs. Window.OnDestroy is a signal fired before the window's resources are cleaned up.

The window can be dragged using its top bar and automatically adjusts its position to stay within the screen boundaries.

Tabs and sections

local Tab = Window:AddTab({ Title = "Main", Icon = "home" })
local Section = Tab:AddSection("General")

Tab:SetTitle("Settings")
Tab:SetIcon("settings")
Section:SetTitle("General settings")
Section:SetVisible(true)

Tabs and sections support the same component methods, including AddButton, AddToggle, AddSlider, and AddDropdown. See the Components page for the full list of available components.

Layout, scrolling, and spacing are handled automatically.

Use Destroy() to remove a tab or section and clean up its associated components and registered resources.

Components

ZETA Pro components share a common API for managing values, appearance, visibility, and lifecycle. Some methods are more relevant to specific component types.

comp:GetValue()            comp:SetValue(v)
comp:OnChanged(function(v) end)
comp:SetTitle("..")        comp:SetDescription("..")
comp:SetIcon("check")      comp:SetIcon(nil)
comp:SetTooltip("..")      comp:SetVisible(false)
comp:SetEnabled(false)     comp:Destroy()

Common configuration options include Title, Description, Icon, Tooltip, Visible, and Enabled. Invalid configuration values, such as Default = "yes" on a Toggle, produce a descriptive [ZETA][ERROR] message.

Button

local Button = Tab:AddButton({
    Title = "Execute",
    Description = "Run an action",
    Icon = "play",
    Callback = function()
        print("Button clicked!")
    end,
})

Buttons execute a callback when clicked. Use Fire() to trigger the callback programmatically, or SetCallback(function) to replace it at runtime.

Toggle

local Toggle = Tab:AddToggle("AutoFarm", {
    Title = "Auto Farm",
    Default = false,
    Callback = function(enabled)
        print("Auto Farm:", enabled)
    end,
})

Toggles control a boolean value (true or false). Use Default to set the initial state and Callback to respond to changes. You can also use GetValue() and SetValue() to read or update the state programmatically.

Slider

local Slider = Tab:AddSlider("Speed", {
    Title = "Walk Speed",
    Min = 16,
    Max = 250,
    Default = 16,
    Increment = 1,
    Rounding = 0,
    Callback = function(value)
        print("Walk Speed:", value)
    end,
})

Sliders let users select a numeric value by dragging the bar or entering a number directly.

Use Min and Max to define the allowed range, Increment to control value steps, and Rounding to set decimal precision. Values are automatically clamped, snapped to the nearest increment, and rounded.

Dropdown and MultiDropdown

local Dropdown = Tab:AddDropdown("Mode", {
    Title = "Mode",
    Values = { "Legit", "Rage", "Silent" },
    Default = 1,
    Callback = function(value)
        print("Selected mode:", value)
    end,
})

local MultiDropdown = Tab:AddDropdown("Targets", {
    Title = "Targets",
    Values = { "Players", "NPCs", "Bosses" },
    Multi = true,
    Default = { Players = true },
    Callback = function(selected)
        print("Players:", selected.Players)
        print("NPCs:", selected.NPCs)
    end,
})

Dropdowns let users select a single option, while MultiDropdowns allow multiple selections.

Use Values to define the available options. For a single Dropdown, Default accepts an option index or name. For a MultiDropdown, use a table of selected names. MultiDropdown callbacks receive a map of all available options with boolean values.

Use SetValues({...}) to replace the available options at runtime. Selections that are no longer valid are removed.

You can also create a multi-selection dropdown using AddMultiDropdown() instead of setting Multi = true.

Input

local Input = Tab:AddInput("Name", {
    Title = "Username",
    Placeholder = "Enter your username...",
    MaxLength = 20,
    Numeric = false,
    Live = false,
    Validate = function(text)
        return #text >= 3
    end,
    Callback = function(value)
        print("Username:", value)
    end,
})

Inputs let users enter text or numeric values. Use Placeholder to display a hint, MaxLength to limit input length, and Numeric to restrict input to valid numbers.

By default, values are committed when the input loses focus. Set Live = true to update the value as the user types, provided the input passes validation.

Use Validate to define custom validation rules. If the input is invalid when focus is lost, the previous valid value is restored and the border briefly flashes red.

Keybind

local Enabled = false
local Keybind = Tab:AddKeybind("ActionKey", {
    Title = "Toggle Action",
    Default = Enum.KeyCode.F,
    Callback = function(key)
        Enabled = not Enabled
        print("Action enabled:", Enabled)
    end,
    ChangedCallback = function(key)
        print("New keybind:", key)
    end,
})

Keybinds let users assign keyboard keys or supported mouse buttons to actions. Callback runs when the assigned input is pressed, while ChangedCallback runs when the binding changes.

Click the keybind field to assign a new input. Press Esc to cancel, Backspace to clear the binding, or right-click to restore the default. Conflicting bindings display a warning.

See the Keybinds page for the complete guide.

Colorpicker

local Colorpicker = Tab:AddColorpicker("Accent", {
    Title = "Accent",
    Default = Color3.fromRGB(255, 255, 255),
    Transparency = 0,
    Callback = function(color, transparency)
        print("Selected color:", color)
        print("Transparency:", transparency)
    end,
})

Colorpickers let users choose colors using a saturation/value square, hue bar, and HEX, RGB, or HSV fields.

Use Transparency to set the alpha value from 0 (opaque) to 1 (transparent).

Use GetHex(), SetTransparency(), GetTransparency(), Reset(), and Copy HEX to inspect or change colors.

Paragraph, Label, Divider

local Paragraph = Tab:AddParagraph({
    Title = "Information",
    Content = "Welcome to ZETA Pro!",
    Icon = "info",
})
local Label = Tab:AddLabel({ Text = "General information" })
Tab:AddDivider({})

Use AddParagraph() to display information with a title, description, and optional icon. Use AddLabel() for a simple text row, or AddDivider() to visually separate components.

Paragraphs support RichText for formatted content. You can update text at runtime using Paragraph:SetContent() or Label:SetText().

Keybinds

Keybinds let users assign customizable keyboard shortcuts or supported mouse buttons to actions. They share a centralized input handler and are automatically unregistered when their components are destroyed.

Basic example

local Enabled = false
local ActionKey = Section:AddKeybind("ActionKey", {
    Title = "Toggle Action",
    Default = Enum.KeyCode.F,
    Callback = function(key)
        Enabled = not Enabled
        print("Action enabled:", Enabled)
    end,
})

Callback runs when the assigned key is pressed and receives the bound input. The optional component ID allows the binding to be managed through Zeta.Config. Keybinds can also be created without an ID.

Initial key

-- Keyboard key
Default = Enum.KeyCode.RightShift
-- Key name as a string
Default = "RightControl"
-- Mouse button
Default = Enum.UserInputType.MouseButton2
-- No initial binding
Default = nil

The Default option defines the initial key or mouse button assigned to a Keybind. It accepts an Enum.KeyCode, a case-sensitive key name string, or a supported mouse button.

Set Default = nil, use "None", or omit the option to start without a binding. Invalid values produce a descriptive [ZETA][ERROR] when the component is created.

Detect rebinding

local FarmKey = Section:AddKeybind("FarmKey", {
    Title = "Farm hotkey",
    Default = "F",
    ChangedCallback = function(key)
        print("New binding:", key.Name)
    end,
})
FarmKey:OnChanged(function(key)
    print("Binding changed:", key.Name)
end)
FarmKey:OnClick(function(key)
    print("Hotkey pressed:", key.Name)
end)

Use ChangedCallback or OnChanged() to detect when a Keybind's assigned input changes. These callbacks receive the new binding and do not run when the assigned key is simply pressed.

Use OnClick() to register an additional callback that runs when the assigned key or mouse button is pressed. This is separate from detecting binding changes.

Change the key at runtime

-- Change the assigned key
ActionKey:SetValue(Enum.KeyCode.E)
-- Key names are also supported
ActionKey:SetValue("Q")
-- Restore the original binding
ActionKey:Reset()
-- Read the current binding
print("Current key:", ActionKey:GetValue().Name)

Use SetValue() to change a Keybind's assigned input programmatically. It accepts an Enum.KeyCode, a supported mouse button, or a valid key name string.

Use GetValue() to retrieve the current binding and Reset() to restore its original Default value.

Players can also click the keybind field to assign a new input. Press Esc to cancel, Backspace to clear the binding, or right-click to restore the default. Conflicting bindings display a warning.

Disable or remove

ActionKey:SetValue(nil)
ActionKey:SetEnabled(false)
ActionKey:SetEnabled(true)
ActionKey:Destroy()

Use SetValue(nil) to clear the assigned key, SetEnabled(false) to temporarily disable the Keybind, and SetEnabled(true) to enable it again. Use Destroy() to permanently remove the component and unregister its binding.

Real example

local Enabled = Section:AddToggle("Enabled", {
    Title = "Enable Feature",
    Default = false,
})
local ToggleKey = Section:AddKeybind("ToggleKey", {
    Title = "Feature Hotkey",
    Description = "Press the assigned key to toggle the feature",
    Default = Enum.KeyCode.F,
    Callback = function()
        Enabled:SetValue(not Enabled:GetValue())
    end,
})

Keybinds can control other components. In this example, pressing F toggles the value of a Toggle component.

GetValue() reads the current state, while SetValue() updates it. This lets users control the same feature through either the Toggle or its assigned keyboard shortcut.

Supported keys

Keybinds support keyboard keys, valid key name strings, and the right and middle mouse buttons.

TypeExamples

When assigning a key through the interface, press Esc or left-click to cancel, or press Backspace to clear the binding. Key names are case-sensitive.

Window key

local Window = Zeta:CreateWindow({
    Title = "My UI",
    MinimizeKey = Enum.KeyCode.RightControl,
})
-- Change the minimize shortcut
Window:SetMinimizeKey(Enum.KeyCode.RightShift)
-- Disable the keyboard shortcut
Window:SetMinimizeKey(nil)

Use MinimizeKey to assign a keyboard shortcut for minimizing and restoring the window. The value must be an Enum.KeyCode; key name strings are not supported for this option.

Use Window:SetMinimizeKey() to change the shortcut at runtime, or pass nil to disable the keyboard shortcut. This does not disable the window's built-in minimize and restore controls.

Dialogs

local Dialog = Window:CreateDialog({
    Title = "Confirm",
    Content = "Are you sure?",
})

Dialog:AddButton({ Title = "Cancel" })
Dialog:AddButton({
    Title = "Confirm",
    Primary = true,
    Callback = function()
        Zeta:Notify({ Title = "Done", Type = "Success" })
    end,
})

Use Window:CreateDialog() to display a modal dialog with a title and optional content.

Call Dialog:AddButton() to add actions. Each button closes the dialog after its callback runs.

Notifications

local Notification = Zeta:Notify({
    Title = "Saved",
    Content = "Settings saved successfully.",
    Type = "Success",
    Duration = 4,
    Progress = true,
    Closable = true,
})
-- Optional: close the notification manually
-- Notification:Close()

Use Zeta:Notify() to display temporary messages. Available notification types are Info, Success, Warning, and Error.

Use Duration to control how long a notification remains visible. Progress displays a countdown bar, while Closable controls whether a close button is shown. Notifications close automatically after their duration, or you can call Close() to dismiss one manually.

Notifications appear in the bottom-right corner, follow the active theme and UI scale, and display up to five messages at once. When the limit is exceeded, the oldest notification closes first.

Themes

Built-in themes: Dark, Light, Midnight, Zeta, and Pure Red. Halloween 2026 is a limited seasonal theme and will be removed after Halloween 2026.

Zeta:SetTheme("Midnight")
print("Current theme:", Zeta:GetTheme())

for _, name in ipairs(Zeta:GetThemes()) do
    print("Available theme:", name)
end

Zeta:RegisterTheme("MyTheme", {
    Base = "Dark",
    Background = Color3.fromRGB(13, 9, 10),
    Secondary = Color3.fromRGB(22, 14, 16),
    Tertiary = Color3.fromRGB(32, 20, 23),
    Text = Color3.fromRGB(240, 232, 233),
    MutedText = Color3.fromRGB(150, 128, 131),
    Accent = Color3.fromRGB(239, 68, 90),
    AccentText = Color3.new(1, 1, 1),
    Border = Color3.fromRGB(48, 30, 34),
})
Zeta:SetTheme("MyTheme")
Zeta:SetFont(Enum.Font.GothamMedium)
Zeta:SetScale(0.9)

Use SetTheme() to change the active theme at runtime and GetTheme() or GetThemes() to inspect current or registered themes.

Use RegisterTheme() to create custom themes by overriding selected color tokens.

Use SetFont() and SetScale() to customize the UI font and scale.

Aliases and inheritance

Secondary and Tertiary are shorthand aliases for SecondaryBackground and TertiaryBackground.

Use Base to inherit colors from an existing theme. Only the tokens you explicitly define are overridden; all remaining tokens retain their inherited or default values.

Theme tokens

GroupTokens
SurfacesBackground, SecondaryBackground, TertiaryBackground, Border, Hover, Pressed, Overlay
Text and accentText, MutedText, Accent, AccentText
StatusSuccess, Warning, Error, Info

Color tokens use Color3, while transparency tokens use numbers. Unspecified values inherit from the base theme or the defaults.

Custom providers

Zeta:RegisterIconProvider("Mine", function(name)
    if name == "logo" then
        return {
            Type = "Image",
            Source = "rbxassetid://123",
            Tint = true,
        }
    end

    return nil
end)

Zeta:SetIconProvider("Mine")

Use RegisterIconProvider() to define a custom icon resolver, then activate it with SetIconProvider().

The active provider is checked first when resolving an icon name. If it returns nil, ZETA Pro attempts to resolve the name through the built-in Lucide catalog.

Custom providers can return an icon specification, such as an image asset. This allows you to use your own icons without modifying the built-in catalog.

Image icons

Section:AddButton({
    Title = "Custom Icon",
    Icon = {
        Type = "Image",
        Source = "rbxassetid://123",
        Tint = false,
    },
    Callback = function()
        print("Button clicked")
    end,
})

You can use your own Roblox image assets as icons by passing an image specification to the Icon property.

Set Type = "Image" and provide a valid Roblox asset ID through Source. Use Tint = true to apply the active theme color, or Tint = false to preserve the image's original colors, which is useful for logos.

Replace the example asset ID with your own valid image asset.

Remote icons

Section:AddButton({
    Title = "Remote Icon",
    Icon = {
        Type = "Url",
        Source = "https://example.com/icon.png",
        Tint = false,
    },
    Callback = function()
        print("Button clicked")
    end,
})

Remote icons allow you to use PNG images hosted on external websites. Set Type = "Url" and provide a direct HTTPS image URL through Source.

Remote images require HTTP requests, filesystem access, and getcustomasset support. Only PNG files up to 256 KB are accepted. Successfully downloaded images are cached in ZetaPro/icons/ for reuse.

If a remote image cannot be loaded, ZETA Pro displays a fallback icon without interrupting the interface. Built-in Lucide icons do not require remote downloads.

Hot swap

-- Change a tab's icon
Tab:SetIcon("settings")
-- Change a component's icon
Component:SetIcon("check")
-- Change it again
Component:SetIcon("circle-check")
-- Remove the component's icon
Component:SetIcon(nil)

Use SetIcon() to change a tab or component icon at runtime. Pass a valid Lucide icon name to replace the current icon, or nil to remove it.

Icons are updated without recreating the tab or component. The layout adjusts automatically when an icon is added or removed.

Compatibility

Existing scripts using built-in Lucide icon names, such as Icon = "home" or Icon = "settings", remain compatible.

External icon family prefixes, such as solar:, geist:, craft:, and sf:, are no longer supported. Replace these references with valid Lucide icon names from icons.rest.

Custom image icons and registered icon providers remain supported.

Config and state

Components created with an ID can store their values in Zeta.Config. Use Set() and Get() to manage values programmatically, or Export() and Import() to transfer configuration data as Luau tables.

-- Set and read a value
Zeta.Config:Set("Speed", 60)
print(Zeta.Config:Get("Speed"))

-- Export and import values
local data = Zeta.Config:Export()
Zeta.Config:Import(data)

-- Restore registered defaults
Zeta.Config:Reset()

-- Save settings to a JSON file
local saved, saveError = Zeta.Config:Save("default")

-- Load settings from a JSON file
local loaded, loadError = Zeta.Config:Load("default")

Use Reset() to restore registered default values. To persist settings between sessions, use Save(name) and Load(name). Configuration files are stored as JSON in ZetaPro/configs/.

Saving and loading require filesystem support. Both methods return true on success or false, reason on failure. Supported values include booleans, numbers, strings, Color3, Enum items, and tables containing supported values.

Capabilities

print("FileSystem:", Zeta.Capabilities.FileSystem)
print("Clipboard:", Zeta.Capabilities.Clipboard)
print("Touch:", Zeta.Capabilities.Touch)

Use Zeta.Capabilities to check whether filesystem access, clipboard support, or touch input is available before using features that depend on them.

Custom components

Register custom components using RegisterComponent(name, factory). Custom component names must be PascalCase, and the factory receives the context, optional component ID, and configuration.

local Stepper = setmetatable({}, { __index = Zeta.Component.Base })
Stepper.__index = Stepper

Zeta:RegisterComponent("Stepper", function(ctx, id, config)
    local self = Zeta.Component.New(ctx, Stepper, "Stepper", id, config, {
        RightWidth = 90,
    })
    -- Build the control inside self.Right and register resources in self.Cleanup.
    return self
end)

local Count = Tab:AddStepper("Count", { Title = "Count" })

This example registers a component skeleton; it does not implement a working stepper control. Add your input widgets to self.Right and register all instances and connections in self.Cleanup.

Troubleshooting

The UI does not load

Library errors use the [ZETA][ERROR] prefix and may name the affected module. Check whether the runtime supports game:HttpGet and loadstring, then inspect the complete error message. Enable Zeta:SetDebug(true) after the library has loaded for additional diagnostic logs.

Loading is slow on mobile

The loader downloads its modules when executed. A slow connection, a blocked request, or delays accessing GitHub can increase load time. Try again when the connection is stable.

My fix is not showing up

raw.githubusercontent.com may cache old files temporarily. Verify the branch being loaded, or use ZETA_BASE to point the loader and its modules at your intended branch or release tag.

Save and Load return false

Check Zeta.Capabilities.FileSystem. File saving requires filesystem support. Load() can also return false, "file not found" if a configuration has not been saved under that name.

Cleaning up

Window:Destroy() cleans up resources managed by one window. Zeta:Unload() unloads the library and resets its notifications and input bindings.

FAQ

Quick answers to common questions.

What is ZETA Pro?

ZETA Pro is an open-source Luau UI library for Roblox script hubs. It provides windows, tabs, sections, common controls, themes, Lucide icons, configurable keybinds, notifications, dialogs, and configuration saving.

How do I install ZETA Pro?

Use the main-branch loader:

local Zeta = loadstring(game:HttpGet("https://raw.githubusercontent.com/realkalii/ZetaPro/main/src/init.luau"))()

See Installation and Quick start for examples.

Does ZETA Pro support themes?

Yes. Permanent built-in themes include Dark, Light, Midnight, Zeta, and Pure Red. Halloween 2026 is seasonal. Use Zeta:RegisterTheme() to add your own and Zeta:SetTheme() to switch. See Themes.

How do icons work?

Use a built-in Lucide name such as "home" or "settings", or provide a custom image or icon provider. The old external icon family prefixes are not supported. See Icons.

Can I create custom components?

Yes. Use Zeta:RegisterComponent(name, factory) to register a factory, then call the corresponding Add<Name>() method on tabs or sections. See Custom components.

Does it work on mobile?

Touch input, dragging and scrolling are supported, and the sidebar adapts to smaller windows. A built-in floating control restores a minimized window. Keyboard shortcuts require a connected keyboard. See Keybinds.

How do I report a bug?

Open an issue on GitHub. Include the complete error, runtime information, a minimal reproduction script, and the behavior you expected. Screenshots help with visual issues.

Where can I get support?

Use the ZETA Pro Discord server for community help and discussion.
